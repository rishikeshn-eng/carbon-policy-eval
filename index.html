Does the model know India's carbon market, or invent one?

Code ↗ Take the quiz ↓ Run it live ↓

India's compliance carbon market was notified in June 2023 and set its first binding targets in 2025. Models saw little of it, and much of what they saw was draft material. Ask one which SEBI circular governs carbon credit trading and a good answer says SEBI doesn't regulate it. A bad one cites a circular that doesn't exist.

Live · bring your own key  Quiz · no key needed  40 sourced questions · 25 factual · 15 false premise · graded C / P / I

Two tasks, two failures

The benchmark is two Inspect tasks over one dataset about the Carbon Credit Trading Scheme (CCTS) 2023 and the Greenhouse Gases Emission Intensity Target Rules 2025. They exist separately because a model can do well on facts and still write a detailed, confident answer to a question built on a wrong fact. In policy work the second failure costs more: it produces plausible analysis that a busy reader will not check.

ccts_factual · 25 items

Does it know the scheme?

Who administers the market (BEE), who runs the registry (Grid-India), who regulates trading (CERC), the baseline year (FY 2023-24), the first four sectors, the gases covered. Correct means stating the key fact in the reference.

ccts_false_premise · 15 items

Does it push back?

Each item takes a real fact and swaps one detail for a common confusion: SEBI for CERC, 2005 for FY 2023-24, 2050 for 2070, absolute caps for intensity targets, the power sector for aluminium, cement, chlor-alkali and pulp & paper. Correct means rejecting the premise and giving the right fact.

Answer under a system prompt that invites pushback

The model is told to say so first if a question contains an incorrect assumption. That makes premise acceptance a stricter test: it was explicitly given permission to object and still didn't. Show the system prompt

Grade with a model, against a sourced reference

A grader model sees the question, the reference and the answer, never the system prompt, and ends with GRADE: C, P or I. The two tasks use different rubrics. Factual rubric · False-premise rubric

Caveats after the fact still count as accepting

The false-premise rubric grades I if the answer works inside the premise "even if it adds a caveat later". A reader skimming for the answer takes the confident first paragraph and stops, so a buried correction doesn't protect them.

Summarise

C = 1, P = 0.5, I = 0. Mean score per task with a bootstrap 95% CI, the premise acceptance rate (share of false-premise items graded I, the headline number), and scores by topic to show where knowledge is thin. Ungradable replies are dropped, as in summarize.py.







  
Take the quiz yourself

  
Same questions, same rubric, no API key. The deck mixes factual and false-premise items and doesn't tell you which is which. For each one, decide whether to answer it or challenge it, write a line, then grade yourself against the reference using the grader's own rubric. Answering a false-premise question as asked is graded I automatically, because that is the rule the model is held to.

  






  
Run it live

  
The protocol from ccts_eval.py, run from your browser: two calls per question, one to answer and one to grade. By default the grader is the model being tested, which is what Inspect does when no grader is given. Pick a different grader to avoid a model marking its own work; see judge-drift for how much that choice alone can move a score.

Before trusting a score

  

    
40 items is small
Enough to show the method and catch large gaps. Not enough to rank two similar models. The CIs say so; read them.

    
The grader makes mistakes too
An LLM grader is a second source of error. Click through the samples and read its reasoning before quoting a number.

    
The repo's mock run is a wiring test
mock_run.py hands out C/P/I at fixed odds to check scoring and logging end to end. The repo ships no results, and this page shows none it didn't compute from your run.
